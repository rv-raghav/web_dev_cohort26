Hoisting

Complete guide — var, function, let, const, arrow functions, and the memory phase

// 00
What is hoisting?
Hoisting is NOT magic. It is the result of how the JS engine's memory creation phase works.

The real definition

Before any code runs, JavaScript scans the entire file and allocates memory for every variable and function declaration. Variables declared with var get memory set to undefined. Function declarations get their entire body stored. This is the memory creation phase — and because declarations are "already known" before execution starts, it appears as if they were moved to the top. That illusion is called hoisting.

Phase 1 — Memory creation

  • JS engine scans the whole file
  • var declarations → set to undefined
  • Function declarations → full body stored
  • Nothing has executed yet

Phase 2 — Code execution

  • Code runs line by line, top to bottom
  • Values are assigned to variables
  • Function calls create new execution contexts
  • Completed contexts are popped off the stack
concept.js 
// ─────────────────────────────────────────────────────────
// PHASE 1  (before any line runs, engine does this in memory)
// ─────────────────────────────────────────────────────────
//
//   x          →  undefined    (var declaration found)
//   getName    →  function() { console.log("...") }  (full body)
//
// ─────────────────────────────────────────────────────────
// PHASE 2  (now execution actually starts from line 1)
// ─────────────────────────────────────────────────────────

var x = 7;          // ← x was undefined in memory; NOW assigned 7

function getName() {
    console.log("My name is hoisting");
    // ↑ full body was already in memory since Phase 1
}

getName();           // ✅ works — body was already stored in Phase 1
console.log(x);       // ✅ 7   — x was assigned just above
console.log(getName); // ✅ prints the full function object
console output
▶My name is hoisting
▶7
▶ƒ getName() { console.log("My name is hoisting") }

// 02
function declaration hoisting
Function declarations are hoisted completely — you can call them before they appear in your code.

Function declarations: fully hoisted

Unlike var, a function declaration is hoisted with its entire body. In Phase 1, the engine stores the complete function. So you can call it from anywhere in the same scope — even on line 1 — before the function keyword appears in your file.

function_hoisting.js works perfectly 
// ── CALLING BEFORE DECLARATION ──────────────────────────────

getName();
// ✅ "My name is hoisting" — works! Engine already stored the body

console.log(getName);
// ✅ prints:  ƒ getName() { console.log("My name is hoisting") }
//            ↑ full function body was in memory since Phase 1


function getName() {
    console.log("My name is hoisting");
}
// ↑ declaration appears here in the file, but it was already
//   fully available from the top because of hoisting


// ── PHASE 1 MEMORY SNAPSHOT ─────────────────────────────────
//
//   getName  →  ƒ () { console.log("My name is hoisting") }
//               ^^^^^ the ENTIRE function body is stored here
//               NOT undefined — the real function object
//

Arrow function hoisting
Arrow functions assigned to var behave like variables — hoisted as undefined, not as a function.

Arrow functions are NOT hoisted as functions

When you write var getName = () => {}, what gets hoisted is getName as a var — set to undefined. The arrow function body is NOT stored in Phase 1. Calling it before assignment throws a TypeError: you're trying to call undefined as a function.

arrow_hoisting.js TypeError if called early 
// ── PHASE 1  (memory allocation) ────────────────────────────
//
//   getName  =  undefined   ← treated as var, NOT as a function
//
// ── PHASE 2  (execution) ─────────────────────────────────────

getName();
// ❌  TypeError: getName is not a function
//     getName is undefined in memory right now
//     you are calling undefined() — that throws

console.log(getName);
// ⚠️  undefined — the var is in memory but holds no function yet


var getName = () => {
    console.log("My name is hoisting");
};
// ↑ assignment happens HERE in Phase 2
//   only AFTER this line does getName hold the arrow function

getName();
// ✅  "My name is hoisting" — now it works, assignment ran above

console.log(getName);
// ✅  ƒ () { console.log("My name is hoisting") }


// ── WHY? ───────────────────────────────────────────────────
//
//  var getName = () => {}  is syntactically:
//    → a var declaration     (hoisted, set to undefined)
//    → with an assignment    (NOT hoisted — stays in Phase 2)
//
//  The arrow function body is the VALUE being assigned.
//  Values are never hoisted. Only declarations are.
//
console output (if code is run top to bottom)
▶TypeError: getName is not a function

var getName = function(){} — function expression
Same behaviour as arrow functions — the variable is hoisted, but the function body is not.
!
Function expression = a function assigned to a variable. It behaves like var hoisting, not like function declaration hoisting. The name is hoisted as undefined; the function body is NOT available until execution reaches the assignment line.
fn_expression_hoisting.js TypeError if called early 
// ── PHASE 1  (memory allocation) ────────────────────────────
//
//   getName  =  undefined   ← var declaration hoisted
//               the function body is NOT stored yet
//

getName();
// ❌  TypeError: getName is not a function
//     Memory at this point:  getName = undefined
//     undefined() throws a TypeError

console.log(getName);
// ⚠️  undefined — var was hoisted but no function assigned yet


var getName = function() {
    console.log("My name is hoisting");
};
// ↑ Phase 2: getName is NOW assigned the function object
//   everything above this line only saw undefined

getName();
// ✅  "My name is hoisting" — assignment already ran

console.log(getName);
// ✅  ƒ () { console.log("My name is hoisting") }


// ── COMPARE THE THREE FORMS ─────────────────────────────────
//
//   function getName()  {}    → FULLY hoisted (declaration)
//   var getName = function(){}→ PARTIALLY hoisted (var = undefined)
//   var getName = () => {}    → PARTIALLY hoisted (var = undefined)
//
//   The difference:  where does the  function  keyword appear?
//   At the start of a statement? → declaration → fully hoisted
//   After  =  (as a value)?      → expression  → only var hoisted
//

// 06
let & const hoisting — the Temporal Dead Zone
let and const ARE hoisted — but they are NOT initialized. Accessing them before declaration throws a ReferenceError.

Temporal Dead Zone (TDZ)

From the start of the block scope until the let or const declaration is reached in code, the variable exists in memory but is in an "uninitialized" state. Any access in this zone throws ReferenceError: Cannot access '...' before initialization. This is the TDZ — the engine knows the variable exists, but deliberately refuses access.

let_const_hoisting.js ReferenceError in TDZ 
// ── var  (silently returns undefined) ───────────────────────

console.log(a);  // ⚠️  undefined  — no error, but surprising
var a = 10;


// ── let  (Temporal Dead Zone — throws ReferenceError) ────────

console.log(b);  // ❌  ReferenceError: Cannot access 'b' before initialization
                  //     b IS in memory (hoisted) but uninitialized — TDZ
let b = 20;


// ── const  (same TDZ behaviour as let) ──────────────────────

console.log(c);  // ❌  ReferenceError: Cannot access 'c' before initialization
const c = 30;


// ── const also requires immediate initialization ─────────────

const d;         // ❌  SyntaxError: Missing initializer in const declaration
                  //     const MUST be declared + assigned on the same line
d = 40;


// ── MENTAL MODEL COMPARISON ─────────────────────────────────
//
//  Memory Phase 1 snapshot:
//
//   var a   →  undefined       ← initialized to undefined, safe to read
//   let b   →  <uninitialized> ← exists but BLOCKED from access (TDZ)
//   const c →  <uninitialized> ← same as let
//
//  The TDZ ends when the engine reaches the declaration line.
//  After that, the variable is accessible normally.
//
console output

▶ReferenceError: Cannot access 'c' before initialization

// Access before assignment: returns undefined (no error)

var x = 7;
console.log(x);                  // ✅  7


// ── CASE 3: var + function expression ────────────────────────
// Phase 1: getName2 = undefined
// Calling before assignment: TypeError

console.log(getName2);           // ⚠️  undefined
// getName2();                   // ❌  TypeError: getName2 is not a function

var getName2 = function() {
    console.log("fn expression");
};
getName2();                      // ✅  "fn expression"  (after assignment)


// ── CASE 4: var + arrow function ─────────────────────────────
// Phase 1: getName3 = undefined
// Calling before assignment: TypeError

console.log(getName3);           // ⚠️  undefined
// getName3();                   // ❌  TypeError: getName3 is not a function

var getName3 = () => {
    console.log("arrow fn");
};
getName3();                      // ✅  "arrow fn"  (after assignment)


// ── CASE 5: let ──────────────────────────────────────────────
// Phase 1: y = <uninitialized>  (TDZ — cannot be touched)
// Access before declaration: ReferenceError

// console.log(y);               // ❌  ReferenceError — TDZ
let y = 20;
console.log(y);                  // ✅  20  (TDZ ended at declaration)


// ── CASE 6: const ────────────────────────────────────────────
// Phase 1: z = <uninitialized>  (TDZ — same as let)
// Must be initialized at declaration — no separate assignment allowed

// console.log(z);               // ❌  ReferenceError — TDZ
const z = 30;
console.log(z);                  // ✅  30
// z = 40;                       // ❌  TypeError: Assignment to constant variable


// ═══════════════════════════════════════════════════════════
// THE GOLDEN RULE
//
//   Only  FUNCTION DECLARATIONS  are fully hoisted.
//   Everything else is either:
//     → undefined  (var)
//     → in TDZ     (let, const)
//     → TypeError  (calling undefined as a function)
//
//   Best practice: always declare before you use.
// ═══════════════════════════════════════════════════════════
1
Function declarations are the only thing fully hoisted. You get the entire function body from line 1 of the file.
2
var declarations are hoisted as undefined. No error — but a silent undefined is often worse because it hides bugs.
3
var + function expression / arrow function: the name is hoisted as undefined. Calling it before the assignment line throws TypeError.
4
let and const enter a Temporal Dead Zone — they are in memory but inaccessible. Any touch before the declaration line throws ReferenceError.
5
The root cause: JavaScript's two-phase execution model. Phase 1 = memory creation. Phase 2 = code runs. Hoisting is just what Phase 1 looks like from Phase 2's perspective.
