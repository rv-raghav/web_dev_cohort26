Introduction to JavaScript
What JavaScript is, where it runs, and why it exists — before writing a single line of code.

What is JavaScript?

JavaScript is a high-level, interpreted, single-threaded, dynamically-typed programming language. Originally created in 1995 to make web pages interactive, it now runs everywhere — browsers, servers (Node.js), mobile apps, IoT devices, and more. It is the only language that runs natively in every browser.

Role in Web Development

  • HTML = structure (skeleton)
  • CSS = style (appearance)
  • JS = behaviour (makes it alive)
  • Runs in the browser's JS engine
  • V8 (Chrome), SpiderMonkey (Firefox)

JS in 2026

  • Most used language worldwide
  • Full-stack with Node.js / Deno / Bun
  • React, Vue, Angular dominate UI
  • TypeScript adds static types on top
  • WebAssembly works alongside it

How JS runs in the browser

The browser has a built-in JS engine. When it encounters a <script> tag, it hands the code to the engine which: (1) parses the code, (2) compiles it to machine code using JIT (just-in-time compilation), (3) executes it. The engine also maintains the call stack, the heap (memory), and communicates with browser APIs for things like timers and network requests.

index.html — embedding JS 
<!-- Three ways to include JavaScript in HTML -->

<!-- 1. Inline script (small snippets only) -->
<script>
  console.log("I run immediately");
</script>

<!-- 2. External file — BEST PRACTICE -->
<!-- defer: runs after HTML is parsed (recommended) -->
<script src="app.js" defer></script>

<!-- 3. Module (enables import/export) -->
<script type="module" src="app.js"></script>

// Rule of thumb:
// Always put <script defer> in <head> or before </body>
// Using defer avoids blocking HTML parsing

Variables — var, let, const
Variables are named containers for data. JavaScript has three ways to declare them — each behaves differently.

The three keywords

var — old way, function-scoped, hoisted as undefined, avoid in modern code.
let — block-scoped, can be reassigned, not accessible before declaration (TDZ).
const — block-scoped, MUST be initialized, cannot be reassigned (but objects/arrays can be mutated).

variables.js 
// ── var ───────────────────────────────────────────────────────
var age = 25;
var age = 30;  // ⚠️ re-declaration allowed — a footgun
age = 35;      // reassignment OK
console.log(age); // 35

// ── let ───────────────────────────────────────────────────────
let score = 100;
// let score = 200;  ❌ SyntaxError: already declared
score = 200;         // ✅ reassignment OK
console.log(score);  // 200

// ── const ─────────────────────────────────────────────────────
const PI = 3.14159;
// PI = 3;  ❌ TypeError: Assignment to constant variable

// const with objects — the REFERENCE is locked, not the contents
const user = { name: "Alice" };
user.name = "Bob";    // ✅ mutating a property — allowed
// user = {};          ❌ reassigning the variable — not allowed
console.log(user.name); // "Bob"

// ── Naming rules ──────────────────────────────────────────────
let myName = "Alice";   // camelCase — standard for variables
const MAX_SIZE = 100;  // SCREAMING_SNAKE_CASE — for constants
let _private = "x";   // _ prefix — convention for private
// let 1thing = "";    ❌ cannot start with digit
// let let = "";       ❌ cannot use reserved keyword

Primitive Data Types
JavaScript has 7 primitive types — these are the basic building blocks of all data.

Primitives vs Objects

Primitives are immutable values stored directly in the variable. When you copy a primitive, you get a completely independent copy. The 7 primitives: string, number, bigint, boolean, undefined, null, symbol. Everything else (arrays, functions, objects) is an object type.

primitives.js 
// ── 1. String ──────────────────────────────────────────────────
let single = 'hello';
let doub   = "world";
let tmpl   = `template ${single}`;  // backtick = template literal
console.log(typeof single);  // "string"

// ── 2. Number ─────────────────────────────────────────────────
let int    = 42;
let float  = 3.14;
let neg    = -7;
let inf    = Infinity;
let notNum = NaN;      // "Not a Number" — result of bad maths
console.log(0.1 + 0.2); // ⚠️  0.30000000000000004 — floating point issue!
console.log(typeof int); // "number"

// ── 3. BigInt ─────────────────────────────────────────────────
let big = 9007199254740991n;  // n suffix = BigInt
console.log(typeof big);       // "bigint"

// ── 4. Boolean ────────────────────────────────────────────────
let isOn  = true;
let isOff = false;
console.log(typeof isOn); // "boolean"

// ── 5. undefined ──────────────────────────────────────────────
let x;
console.log(x);          // undefined — declared but no value
console.log(typeof x);   // "undefined"

// ── 6. null ───────────────────────────────────────────────────
let empty = null;
console.log(empty);          // null — intentionally empty
console.log(typeof empty);   // ⚠️  "object" — famous JS bug, not a real object

// ── 7. Symbol ─────────────────────────────────────────────────
let sym1 = Symbol("id");
let sym2 = Symbol("id");
console.log(sym1 === sym2); // false — every Symbol is unique

// ── typeof operator ───────────────────────────────────────────
console.log(typeof "hi");        // "string"
console.log(typeof 42);          // "number"
console.log(typeof true);        // "boolean"
console.log(typeof undefined);   // "undefined"
console.log(typeof null);        // "object" ← the famous bug
console.log(typeof {});           // "object"
console.log(typeof []);           // "object" ← arrays are objects too
console.log(typeof function(){}); // "function"
key gotchas
▶0.1 + 0.2 = 0.30000000000000004← floating point imprecision
▶typeof null = "object"← historic JS bug, not fixable
▶typeof [] = "object"← use Array.isArray() to check
⚠
Truthy vs Falsy: In conditionals JS coerces values to boolean. Falsy values: false, 0, "", null, undefined, NaN. Everything else is truthy — including [], {}, and "0".
// 04
Types of Operators
Operators act on values. JavaScript has arithmetic, comparison, logical, assignment, bitwise, and special operators.
operators.js 
// ── ARITHMETIC ────────────────────────────────────────────────
console.log(10 + 3);   // 13   addition
console.log(10 - 3);   // 7    subtraction
console.log(10 * 3);   // 30   multiplication
console.log(10 / 3);   // 3.333...   division
console.log(10 % 3);   // 1    modulo (remainder)
console.log(2 ** 8);   // 256  exponentiation
let n = 5;
console.log(n++);     // 5  — post-increment: returns THEN increments
console.log(++n);     // 7  — pre-increment:  increments THEN returns

// ── COMPARISON ────────────────────────────────────────────────
console.log(5 == "5");   // ⚠️  true  — loose equality, coerces type
console.log(5 === "5");  // ✅  false — strict equality, checks type too
console.log(5 != "5");   // false — loose inequality
console.log(5 !== "5");  // true  — strict inequality
console.log(5 > 3);      // true
console.log(5 >= 5);     // true
// RULE: ALWAYS use === instead of == to avoid type coercion bugs

// ── LOGICAL ──────────────────────────────────────────────────
console.log(true && false); // false  — AND: both must be truthy
console.log(true || false); // true   — OR: at least one truthy
console.log(!true);          // false  — NOT: inverts boolean

// Short-circuit evaluation — very important!
const a = null;
console.log(a || "default");  // "default" — a is falsy, returns right side
console.log(a && "value");   // null — a is falsy, short-circuits

// ── NULLISH COALESCING (??) — ES2020 ─────────────────────────
const val = null ?? "fallback"; // "fallback"
const zero = 0 ?? "fallback";   // 0  ← ?? only triggers on null/undefined, not 0 or ""
// Prefer ?? over || when 0 or "" are valid values

// ── ASSIGNMENT ────────────────────────────────────────────────
let x = 10;
x += 5;   // x = x + 5 = 15
x -= 3;   // x = x - 3 = 12
x *= 2;   // x = x * 2 = 24
x /= 4;   // x = x / 4 = 6
x **= 2;  // x = x ** 2 = 36

// ── SPECIAL: typeof, instanceof, in ──────────────────────────
console.log(typeof "hi");           // "string"
console.log([] instanceof Array);   // true
console.log("name" in { name: "x" }); // true — property exists in object
key gotcha
▶5 == "5" → trueloose equality coerces type — always use ===
▶0 ?? "fallback" → 0?? only catches null/undefined, not falsy

Conditionals — if/else, switch, ternary
Control which code runs based on conditions.
conditionals.js 
// ── if / else if / else ───────────────────────────────────────
const score = 72;

if (score >= 90) {
  console.log("A grade");
} else if (score >= 70) {
  console.log("B grade");   // ← this runs
} else if (score >= 50) {
  console.log("C grade");
} else {
  console.log("Fail");
}

// ── Ternary operator ──────────────────────────────────────────
// condition ? valueIfTrue : valueIfFalse
const age = 20;
const status = age >= 18 ? "adult" : "minor";
console.log(status); // "adult"

// Nested ternary — use sparingly, hard to read
const grade = score >= 90 ? "A"
            : score >= 70 ? "B"
            : score >= 50 ? "C"
            : "F";

// ── switch ────────────────────────────────────────────────────
const day = "Monday";

switch (day) {
  case "Monday":
    console.log("Start of the week");
    break;            // ← MUST have break or it falls through!
  case "Friday":
    console.log("End of the week");
    break;
  case "Saturday":
  case "Sunday":     // fall-through: both cases run same code
    console.log("Weekend!");
    break;
  default:
    console.log("Midweek");
}

// ── switch gotcha: missing break ──────────────────────────────
switch (1) {
  case 1:
    console.log("one");   // ← runs
    // no break! falls through
  case 2:
    console.log("two");   // ← also runs! fall-through
    break;
  case 3:
    console.log("three"); // does NOT run
}

// ── optional chaining in conditions ──────────────────────────
const user = null;
if (user?.name) {        // safely checks — no TypeError if user is null
  console.log(user.name);
}
console output
▶B grade
▶adult
▶Start of the week
▶one two← fall-through when break is missing

Loops — while, for, for…of, for…in
Loops repeat code. JavaScript has multiple loop types — each for different use cases.
loops.js 
// ── while loop ────────────────────────────────────────────────
// Use when you don't know how many iterations up front
let i = 0;
while (i < 3) {
  console.log(`while: ${i}`);
  i++;
}
// while: 0 → while: 1 → while: 2

// do...while — always runs at least once
let j = 5;
do {
  console.log(`do: ${j}`);  // runs once even though j > 3
  j++;
} while (j < 3);

// ── for loop ──────────────────────────────────────────────────
// Use when you know the number of iterations
// for (initializer; condition; update)
for (let i = 0; i < 5; i++) {
  if (i === 3) continue;  // skip iteration 3
  if (i === 4) break;    // stop loop entirely at 4
  console.log(`for: ${i}`);
}
// for: 0 → for: 1 → for: 2  (3 skipped, 4 breaks)

// ── for...of — iterating VALUES ──────────────────────────────
// Use for arrays, strings, Sets, Maps — anything iterable
const fruits = ["apple", "banana", "cherry"];
for (const fruit of fruits) {
  console.log(fruit);  // apple → banana → cherry
}

// with index using entries()
for (const [index, fruit] of fruits.entries()) {
  console.log(`${index}: ${fruit}`);  // 0: apple → 1: banana → 2: cherry
}

// ── for...in — iterating KEYS of an object ───────────────────
const person = { name: "Alice", age: 25, city: "NY" };
for (const key in person) {
  console.log(`${key}: ${person[key]}`);
  // name: Alice → age: 25 → city: NY
}
// ⚠️ for...in also iterates inherited properties — use hasOwnProperty check
// ⚠️ don't use for...in on arrays — use for...of or forEach instead

// ── Infinite loop guard ───────────────────────────────────────
// while (true) {}  ← NEVER do this without a break condition
//                     it freezes the browser tab
when to use which loop
▶for loop← when you know the count
▶while loop← when condition-driven
▶for...of← iterating array/string values
▶for...in← iterating object keys only
