Introduction to OOP
Object-Oriented Programming organises code around objects that combine data (properties) and behaviour (methods).

The four pillars of OOP

Encapsulation — bundle data + methods, hide internal details, expose only what's needed.
Inheritance — child classes inherit properties and methods from parent classes, avoiding repetition.
Polymorphism — different objects respond to the same method call in different ways.
Abstraction — expose a simple interface, hide complex implementation.

JS OOP: prototype-based, not class-based

Unlike Java or C++, JavaScript's OOP is prototype-based. Every object has an internal link ([[Prototype]]) to another object. The class syntax introduced in ES6 is syntactic sugar — it creates constructor functions and sets up the prototype chain under the hood. Classes make the code look familiar, but the engine still uses prototypes.

oop_intro.js 
// ── The problem OOP solves ────────────────────────────────────

// Without OOP: unrelated data, repeated code
const user1Name  = "Alice";
const user1Age   = 25;
const user2Name  = "Bob";
const user2Age   = 30;

// With OOP: data + behaviour bundled together
class User {
  constructor(name, age) {
    this.name = name;
    this.age  = age;
  }
  greet() {
    return `Hi, I'm ${this.name} and I'm ${this.age}`;
  }
}

const alice = new User("Alice", 25);
const bob   = new User("Bob", 30);

console.log(alice.greet());  // "Hi, I'm Alice and I'm 25"
console.log(bob.greet());   // "Hi, I'm Bob and I'm 30"

// Both instances share the greet() method via prototype
// (not duplicated in memory for each instance)
console.log(alice.greet === bob.greet);  // true — same function

Classes & Objects
Classes are blueprints for creating objects. They define the shape (properties) and behaviour (methods) of every instance.
classes.js 
class Animal {
  // Class field (modern syntax — no constructor needed for simple props)
  species = "Unknown";

  // Static field — belongs to the class, not instances
  static count = 0;

  constructor(name, sound) {
    this.name  = name;
    this.sound = sound;
    Animal.count++;   // track how many animals created
  }

  // Instance method — available on every instance
  speak() {
    return `${this.name} says ${this.sound}`;
  }

  // Getter — accessed as property, not called as method
  get info() {
    return `${this.name} (${this.species})`;
  }

  // Setter — intercepts property assignment
  set nickname(value) {
    this._nickname = value.trim().toLowerCase();
  }
  get nickname() { return this._nickname; }

  // Static method — called on the class, not instances
  static compare(a, b) {
    return a.name.localeCompare(b.name);
  }

  // toString — called when object is used as string
  toString() {
    return `Animal(${this.name})`;
  }
}

const cat = new Animal("Cat", "meow");
const dog = new Animal("Dog", "woof");

console.log(cat.speak());       // "Cat says meow"
console.log(cat.info);          // "Cat (Unknown)" — getter, no ()
cat.nickname = "  Kitty  ";
console.log(cat.nickname);      // "kitty" — setter trimmed + lowercased
console.log(Animal.count);     // 2 — static field on the class
console.log(Animal.compare(cat, dog));  // negative (Cat before Dog)

// instanceof check
console.log(cat instanceof Animal);  // true

// Class expressions (less common, same power)
const Point = class {
  constructor(x, y) { this.x = x; this.y = y; }
  toString() { return `(${this.x},${this.y})`; }
};

Constructors & the "this" keyword
The constructor initialises new instances. this refers to the current object — but its value depends on how a function is called.

this — the most confusing part of JS

this is not determined by where a function is written — it's determined by how it is called. In a class constructor and methods, this refers to the new instance. But pass the method as a callback and this changes. Arrow functions solve this by inheriting this from their enclosing lexical scope.

constructors_this.js 
// ── What new does ─────────────────────────────────────────────
// When you call  new ClassName():
// 1. Creates a new empty object {}
// 2. Sets __proto__ to ClassName.prototype
// 3. Binds  this  to the new object
// 4. Executes the constructor body
// 5. Returns the new object (unless constructor returns an object)

class Timer {
  constructor(label) {
    this.label   = label;
    this.seconds = 0;
  }

  // ❌ Regular method — this is lost when passed as callback
  tickBroken() {
    this.seconds++;
    console.log(`${this.label}: ${this.seconds}s`);
  }

  // ✅ Arrow class field — this is always bound to the instance
  tick = () => {
    this.seconds++;
    console.log(`${this.label}: ${this.seconds}s`);
  }
}

const t = new Timer("workout");
t.tick();                           // ✅ workout: 1s
setTimeout(t.tick, 1000);           // ✅ works — arrow preserves this
// setTimeout(t.tickBroken, 1000);   ❌ this is undefined in strict mode

// ── this contexts ─────────────────────────────────────────────

// 1. Global context
console.log(this);  // window (browser) or {} (Node module)

// 2. Regular function — this depends on caller
function whoAmI() { return this; }
whoAmI();           // window (sloppy) or undefined (strict mode)

// 3. Method call — this = the object before the dot
const obj = { name: "obj", who() { return this.name; } };
obj.who();  // "obj"

// 4. Detached method — this is lost!
const fn = obj.who;
fn();  // undefined — this is no longer obj

// 5. Arrow function — lexical this (from enclosing scope)
const obj2 = {
  name: "obj2",
  regular() {
    const arrow = () => this.name;  // inherits this from regular()
    return arrow();
  }
};
obj2.regular();  // "obj2" — arrow captures this from regular()

// 6. new keyword — this = new instance
function Person(name) { this.name = name; }
const p = new Person("Alice");
console.log(p.name);  // "Alice"

Inheritance with extends & super
Child classes inherit from parent classes using extends. super calls the parent's constructor or methods.
inheritance.js 
class Animal {
  constructor(name, age) {
    this.name = name;
    this.age  = age;
  }
  speak() { return `${this.name} makes a sound`; }
  describe() { return `${this.name}, age ${this.age}`; }
}

class Dog extends Animal {
  constructor(name, age, breed) {
    super(name, age);  // MUST call super() before using this
    this.breed = breed;
  }

  // Override parent method
  speak() {
    return `${this.name} barks: WOOF!`;
  }

  // Extend parent method using super
  describe() {
    return `${super.describe()} — ${this.breed}`;
    //       ↑ calls Animal.describe()
  }

  fetch() { return `${this.name} fetches the ball!`; }
}

class ServiceDog extends Dog {
  constructor(name, age, breed, task) {
    super(name, age, breed);  // calls Dog constructor
    this.task = task;
  }
  describe() {
    return `${super.describe()} — trained for ${this.task}`;
  }
}

const d  = new Dog("Rex", 3, "Labrador");
const sd = new ServiceDog("Buddy", 5, "Golden", "guiding");

console.log(d.speak());     // "Rex barks: WOOF!"
console.log(d.describe());  // "Rex, age 3 — Labrador"
console.log(d.fetch());     // "Rex fetches the ball!"
console.log(sd.describe()); // "Buddy, age 5 — Golden — trained for guiding"

// instanceof checks the entire chain
console.log(sd instanceof ServiceDog); // true
console.log(sd instanceof Dog);         // true
console.log(sd instanceof Animal);      // true

// Mixin pattern — multiple inheritance workaround
const Swimmable = (Base) => class extends Base {
  swim() { return `${this.name} swims`; }
};
const Flyable = (Base) => class extends Base {
  fly() { return `${this.name} flies`; }
};
class Duck extends Swimmable(Flyable(Animal)) {}
const duck = new Duck("Donald", 4);
console.log(duck.swim());  // "Donald swims"
console.log(duck.fly());   // "Donald flies"

Prototypal Inheritance — under the hood
Classes are syntax sugar. Understanding the prototype chain reveals how JS inheritance actually works at the engine level.

The prototype chain

Every object has a hidden [[Prototype]] property (accessible as __proto__ or via Object.getPrototypeOf()). When you access a property, JS first looks on the object itself. If not found, it walks up the prototype chain — object → constructor.prototype → parent.prototype → Object.prototype → null. This is how methods are shared without being duplicated.

prototype_chain.js 
// ── Pre-class prototype syntax (what classes compile to) ──────
function Animal(name) {
  this.name = name;    // own property — on each instance
}
Animal.prototype.speak = function() {
  return `${this.name} speaks`;
};  // shared method — on the prototype, NOT on each instance

const cat = new Animal("Cat");
console.log(cat.name);   // "Cat" — own property
console.log(cat.speak()); // "Cat speaks" — found on prototype

// ── The chain visualised ──────────────────────────────────────
//
//   cat (instance)
//    │  .name = "Cat"         ← own property
//    └─ [[Prototype]] → Animal.prototype
//                        │  .speak = function()  ← shared
//                        └─ [[Prototype]] → Object.prototype
//                                            │  .toString, .hasOwnProperty…
//                                            └─ [[Prototype]] → null
//

console.log(Object.getPrototypeOf(cat) === Animal.prototype);  // true
console.log(cat.hasOwnProperty("name"));  // true  — own property
console.log(cat.hasOwnProperty("speak")); // false — on prototype

// ── Property lookup order ─────────────────────────────────────
const obj = Object.create({ shared: "from proto" });
obj.own = "own prop";
console.log(obj.own);    // "own prop" — found on instance first
console.log(obj.shared); // "from proto" — walks up chain
console.log(obj.missing);// undefined — reached end of chain

// ── Extending prototype (pre-class way) ───────────────────────
function Dog(name, breed) {
  Animal.call(this, name);  // call parent constructor
  this.breed = breed;
}
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;  // fix constructor reference
Dog.prototype.bark = function() { return "Woof!"; };

const dog = new Dog("Rex", "Lab");
console.log(dog.speak()); // "Rex speaks" — inherited from Animal
console.log(dog.bark());  // "Woof!"

// ── ES6 class compiles to exactly this ───────────────────────
// class Dog extends Animal {}
// is syntactic sugar for the Dog/Animal prototype setup above

Polymorphism
Different objects respond to the same method call in their own way. Write code that works on any object with the right interface.

Polymorphism = many forms

Polymorphism means you can call the same method on different objects and each responds appropriately. You don't need to know the specific type — just the interface. This enables writing code that's open to extension without modification (Open/Closed Principle).

polymorphism.js 
class Shape {
  area()      { throw new Error("area() must be implemented"); }
  perimeter() { throw new Error("perimeter() must be implemented"); }
  describe()  { return `Area: ${this.area().toFixed(2)}`; }
}

class Circle extends Shape {
  constructor(radius) { super(); this.radius = radius; }
  area()      { return Math.PI * this.radius ** 2; }
  perimeter() { return 2 * Math.PI * this.radius; }
}

class Rectangle extends Shape {
  constructor(w, h) { super(); this.w = w; this.h = h; }
  area()      { return this.w * this.h; }
  perimeter() { return 2 * (this.w + this.h); }
}

class Triangle extends Shape {
  constructor(base, height, a, b, c) {
    super(); this.base = base; this.height = height;
    this.sides = [a, b, c];
  }
  area()      { return 0.5 * this.base * this.height; }
  perimeter() { return this.sides.reduce((a, b) => a + b, 0); }
}

// ── Polymorphic function — works with ANY Shape subclass ──────
function printShapeInfo(shape) {
  // doesn't care if it's Circle, Rectangle, or Triangle
  console.log(shape.describe());
  console.log(`Perimeter: ${shape.perimeter().toFixed(2)}`);
}

const shapes = [
  new Circle(5),
  new Rectangle(4, 6),
  new Triangle(3, 4, 3, 4, 5)
];

shapes.forEach(printShapeInfo);
// Area: 78.54  /  Area: 24.00  /  Area: 6.00

// Total area — same call on all shapes
const totalArea = shapes.reduce((sum, s) => sum + s.area(), 0);
console.log(`Total: ${totalArea.toFixed(2)}`);  // Total: 108.54

Encapsulation — Private & Protected
Encapsulation hides internal state and exposes only what's needed. JS now has true private fields via the # syntax.
encapsulation.js 
// ── TRUE private fields — # syntax (ES2022) ───────────────────
class BankAccount {
  #balance = 0;          // # = truly private field
  #transactionLog = [];   // not accessible outside class at all
  static #interestRate = 0.05;  // private static field

  constructor(owner, initialBalance = 0) {
    this.owner = owner;
    if (initialBalance < 0) throw new Error("Initial balance cannot be negative");
    this.#balance = initialBalance;
  }

  deposit(amount) {
    this.#validate(amount);  // call private method
    this.#balance += amount;
    this.#transactionLog.push({ type: "deposit", amount });
  }

  withdraw(amount) {
    this.#validate(amount);
    if (amount > this.#balance) throw new Error("Insufficient funds");
    this.#balance -= amount;
    this.#transactionLog.push({ type: "withdraw", amount });
  }

  // Private method — only callable inside the class
  #validate(amount) {
    if (amount <= 0) throw new Error("Amount must be positive");
  }

  // Public getter — read-only access to private field
  get balance() { return this.#balance; }

  get history() {
    return [...this.#transactionLog];  // return copy, not original
  }

  static get interestRate() { return BankAccount.#interestRate; }
}

const acc = new BankAccount("Alice", 100);
acc.deposit(50);
acc.withdraw(30);
console.log(acc.balance);    // 120 — via getter
console.log(acc.history);    // [{deposit,50},{withdraw,30}]
// console.log(acc.#balance); ❌ SyntaxError — truly private

// ── Convention-based "protected" (underscore prefix) ──────────
// Before #, developers used _prefix to signal "internal use only"
class Base {
  _protected = "internal";  // convention only — still accessible
}
class Child extends Base {
  read() { return this._protected; }  // "protected" — used by subclasses
}
encapsulation summary
▶#field — truly private (ES2022), enforced by engine
▶_field — convention only, still accessible (legacy)
▶WeakMap — private data via closure (pre-# technique)
▶getter/setter — controlled public interface to private state
